# Chronoverse REST contract

Base `/api`, JSON. Datetimes ISO 8601 UTC; date-only accepted as midnight UTC. Demo defaults `valid_at=2026-09-12T00:00:00Z`, `known_at=2026-09-12T23:59:59Z`. IDs are opaque strings. Errors HTTP 404/409/422 with `detail`. CORS permits localhost dev ports 5173, 4173.

`GET /health` → `{status:"ok"}`.
`GET /api/meta?known_at=...` → `{worlds:string[],planes:string[],perspectives:string[],defaults:{valid_at,known_at,world,plane,perspective},counts:{assertions,events},retrieval:{name,description},examples:[{label,query,valid_at,known_at,plane,world,perspective}]}`.

`POST /api/query` body `{query:string,valid_at?:string,known_at?:string,world?:string,plane?:string,perspective?:string,limit?:number,include_retired?:boolean}`. Scope defaults world `main`, plane `all`, perspective `all`, limit 20. Returns `{query,scope:{valid_at,known_at,world,plane,perspective},results:Assertion[],conflicts:[{subject,predicate,assertion_ids:string[],objects:string[],explanation}],graph:{nodes:[{id,label,kind:"entity"}],edges:[{id,source,target,label,assertion_id,plane,status}]},explanation:string,eligible_count:number,retrieval:{name,description}}`.

Assertion shape: `{id,subject,predicate,object,world,plane,perspective,valid_from,valid_to:string|null,recorded_at,status:"active"|"superseded"|"corrected"|"retracted",effective_valid_to:string|null,summary,evidence:[{id,title,url:string|null,text,recorded_at,synthetic:boolean}],events:[{id,assertion_id,type:"supersede"|"correct"|"retract",effective_at,recorded_at,reason,source,replacement_id:string|null}],score:number,score_breakdown:{lexical:number,vector:number,graph:number},explanation:string}`. Query returns events/evidence known by `known_at`; detail returns history known by optional `known_at`. Default vectors are deterministic hashed lexical vectors, not pretrained semantic embeddings. When `CHRONOVERSE_EMBEDDINGS=semantic`, vectors use locally cached `sentence-transformers/all-MiniLM-L6-v2` (384 dimensions). Retrieval metadata names the active engine. Local dense inference includes visible evidence text, runs only after scope/time filtering, and does not send document text over the network. Missing model returns HTTP 503 with setup guidance; no silent fallback. Graph uses only filtered results. Node identity and one-hop support are scoped by world, plane and perspective; identical labels in different scopes never become the same node. `include_retired=true` allows superseded/corrected/retracted records for exploration, still enforcing world/plane/perspective, recorded_at and original valid intervals.

`GET /api/assertions` accepts same scope fields as query plus `query` and returns same query response. `GET /api/assertions/{id}?known_at=...&valid_at=...` → Assertion including visible history. Defaults dates as above.

`POST /api/assertions` → Assertion (201). Body `{id?:string,subject,predicate,object,world?:"main",plane?:"fact",perspective?:"general",valid_from,valid_to?:null,recorded_at?:string,summary?:string,evidence:[{title,url?:null,text,recorded_at?:string,synthetic?:false}]}`. At least one evidence entry mandatory. Raw document text belongs in `evidence[].text`; assertions are manually supplied, not extracted automatically. Optional `id` is an idempotency key: identical replay returns existing assertion; changed payload returns 409. Recorded time defaults current UTC.

`POST /api/assertions/{id}/events` → Event (201). Body `{id?:string,type:"supersede"|"correct"|"retract",effective_at,recorded_at?:string,reason,source,replacement_id?:null}`. Supersede/correct require existing replacement_id in same world, plane, perspective, subject, predicate. Idempotent `id` supported. Replacement must be known by event recorded_at, cover event effective_at in its original valid interval, and be active in that snapshot. Lifecycle lineage cannot cycle. Each assertion accepts one supersession successor; later transitions attach to the replacement. Events cannot predate their assertion recorded_at or valid_from. All events are visible only when `recorded_at <= known_at` and affect status when `effective_at <= valid_at`. Supersession closes the original valid interval from effective_at once known. Corrections/retractions change acceptability from effective_at once known; use the original valid_from as effective_at for a retroactive correction. Status follows effective-time order, with same-boundary precedence retract > correct > supersede, then recorded_at/id as deterministic ties. Event history remains in recorded order. Replacements remain independent assertions; no destructive update.

`POST /api/evaluate` body `{}` → `{dataset,disclaimer,cases:[{name,query:QueryRequest,expected_ids,baseline_ids,chronoverse_ids,baseline_pass,chronoverse_pass,explanation}],summary:{cases,baseline_passed,chronoverse_passed}}`. Demonstrates temporal/scope correctness on synthetic fixtures only; not general retrieval accuracy.

Python shared API: `Store(path, seed=True)`, `.meta(known_at=...)`, `.query(QueryRequest(...))`, `.get_assertion(id, known_at=..., valid_at=...)`, `.add_assertion(AssertionInput(...))`, `.add_event(id, EventInput(...))`, `.evaluate()`, `.close()`. Validation models in `chronoverse.models`. `create_app(db_path=None)` in `chronoverse.api`; env `CHRONOVERSE_DB` default `data/chronoverse.sqlite3`.

Metadata dimensions/counts are filtered by known_at (default demo end-of-day); the schema planes and synthetic example catalog are static educational metadata. Query conflict detection runs before the result limit, so conflict IDs can include eligible records omitted by display truncation. Different objects are reported as potential conflicts; multivalued predicates may legitimately have multiple objects. No canonical adjudication policy is implemented.

SQLite assertions/events reject UPDATE and DELETE with immutable-ledger triggers. Explicit IDs are idempotent request keys; conflicting replays return 409. `BEGIN IMMEDIATE` serializes competing API/MCP writes across connections. Default record timestamps are captured once per successful insertion. API and MCP share one local database path.

Production static directory may be set with `CHRONOVERSE_STATIC_DIR`; source checkout default is `frontend/dist`. This local profile is unauthenticated and must bind to localhost or be reached through a private tunnel. Azure public multi-user deployment requires an independently implemented access boundary.

Profile-aware extensions and file uploads are specified in [profiles-api-contract.md](profiles-api-contract.md). Evaluation case `query` is a complete QueryRequest object (including query text and scope fields), not a string.
