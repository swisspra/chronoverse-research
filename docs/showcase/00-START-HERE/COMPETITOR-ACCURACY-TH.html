แนวคิดพื้นฐาน 4 ข้อ

1. นาฬิกาสองเรือน

ข้อมูลชิ้นหนึ่งมีเวลาสองแบบที่ไม่เท่ากัน และระบบส่วนใหญ่รู้จักแค่เรือนแรก

พอมีการแก้ไขย้อนหลัง ระบบที่มีนาฬิกาเรือนเดียวจะตอบผิด เพราะเอาข้อมูลที่แก้แล้ว ไปตอบคำถามของคนที่ยังไม่ได้รับการแก้

2. ลำดับการกรอง สำคัญกว่าตัวกรอง

นี่คือหัวใจของทั้งโปรเจกต์ คิดภาพห้องสมุดที่หยิบเอกสารได้ 8 ใบเท่านั้น

ทำไม postfilt ไม่ช่วยเลย เพราะโควตา 8 ใบถูกใช้ไปแล้วตั้งแต่ตอนหยิบ ทิ้งทีหลังไม่ได้ทำให้ใบที่ถูกกลับเข้ามา บทเรียนคือ “กรองก่อนค้น” ไม่เท่ากับ “ค้นก่อนกรอง” และเรื่องนี้พิสูจน์ซ้ำได้ทั้งบนข้อมูลสังเคราะห์และข้อมูลจริง

3. item view — ยุบให้เหลือเวอร์ชันล่าสุดต่อหนึ่งสินค้า

ราคาสินค้าตัวหนึ่งถูกประกาศใหม่ทุกสัปดาห์ จึงมีหลายเวอร์ชัน item view คือการเก็บเฉพาะเวอร์ชันล่าสุดของแต่ละสินค้า แล้วตัดสัปดาห์อื่นทิ้ง

ขั้นตอนการทดลอง

ทำไมถึงเชื่อตัวเลขชุดนี้ได้

  1. เตรียมคลัง รายงานราคารายสัปดาห์ 55 ฉบับ ปี 2025 — 51 issue, 14 ซีรีส์สินค้า ราว 134,000 token
  2. สร้างเฉลยด้วยเครื่อง ไม่ใช้ AI ตัดสิน แกะตารางราคาออกมา 660 แถว เฉลยมาจากตัวเลขตรง ๆ
  3. สุ่มคำถาม 100 ข้อ จากผู้สมัคร 598 ข้อ ด้วย seed 20260913 ทำซ้ำได้
  4. รันทุก arm ด้วยเงื่อนไขเดียวกันเป๊ะ โมเดลตอบตัวเดียวกัน temperature 0 ค้นได้ 8 ชิ้นเท่ากัน
  5. ตรวจว่าโมเดลที่ตอบคือตัวที่ขอจริง proxy เคยสลับโมเดลให้เงียบ ๆ ทุก runner จึงเทียบชื่อโมเดลที่ตอบกลับมาแล้วหยุดทันทีถ้าไม่ตรง
  6. วัดความต่างแบบจับคู่ (exact McNemar) ไม่ได้ดูแค่ว่าได้กี่เปอร์เซ็นต์ แต่ดูทีละข้อว่าข้อไหนที่ A ถูกแล้ว B ผิด

ระหว่างทางเจอบั๊กสองอย่าง และบันทึกไว้ทั้งคู่ ชื่อเกรดสินค้าถูกตัดเหลือสามคำ ทำให้ HDPE Injection สามแบบกลายเป็นอันเดียวกัน — รันรอบนั้นทิ้งทั้งรอบ ไม่รายงาน และการตัด chunk สำคัญกว่านโยบายเวลา — index แรกตัดกลางตารางราคา ทุก arm ตกเหลือ 25–33% พอให้แต่ละแถวราคาเป็น chunk ของตัวเอง (970 chunk) ตัวเลขถึงขึ้นมาเป็นอย่างที่เห็น

การยืนยันแบบ out-of-sampleยังไม่ได้ทำ ดังนั้น 100% ยังเป็น in-sample
คำถามรูปแบบอื่น เช่น ช่วงเวลา เปรียบเทียบ ขอเวอร์ชันเก่ายังไม่ทดสอบ ทั้ง 100 ข้อเป็นรูปเดียวคือ “ณ วัน D ค่าล่าสุดของ S”
การกู้คืนจากการแก้ไขบนข้อมูลจริงcorpus นี้ไม่มีการแก้ย้อนหลังเลย 460 ตรง 0 ขัดแย้ง จึงพิสูจน์ได้แค่บนข้อมูลสังเคราะห์

บนคลังลิขสิทธิ์ของบุคคลที่สาม เมื่อให้วันที่ไปในคำถามแล้ว LightRAG 1.5.7 ตอบถูก 28.0% จาก 100 ข้อ และแพ้ 72 ข้อให้กับวิธีที่กรองเวลาก่อนค้น โดยไม่ชนะกลับเลยสักข้อ ด้วยต้นทุน inference ราว 2% ส่วนเมื่อเทียบกับ long context บนข้อมูลสังเคราะห์ ความแม่นเสมอกัน สิ่งที่ต่างคือการอ้างอิงเก่าเป็น 0% และใช้ token น้อยลง 55–59%

ประโยคอื่นนอกจากนี้ ต้องพ่วงข้อแม้ของมันไปด้วยเสมอ

การเผยแพร่ หน้านี้มีแต่ตัวเลขผลวัด วิธีการ และชื่อซีรีส์สินค้า ไม่มีราคาจริง ไม่มีข้อความจากรายงาน ไม่มีคำตอบดิบของโมเดล ตรงตามข้อกำหนด “แค่ห้ามเผยแพร่ต่อ” คือใช้และเผยแพร่ผลวัดได้ แต่ห้ามส่งต่อตัวคลังข้อมูล
